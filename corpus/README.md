# Real corpus

Real calendar exports, passed through the Calendrum anonymizer (`./gradlew :tools:anonymize`), with golden tests that
read each of them back. Only the anonymizer's output is ever stored here, never a raw export, and every file is read by a
person before it is added.

## Private by design

Even anonymized, a real calendar keeps its structure: the schedule, the number of attendees, the client. So the files
stay with whoever exported them and never go into the repository. `.gitignore` keeps out `corpus/real/` and every file or
directory named `real-*` or `seed-real-*`: conformance cases cut from these files (`conformance/ical/real-*`), fuzz inputs
grown from them and golden files derived from them.

A checkout without them builds and passes: `RealCorpusTest` and the benchmark tests of real files are skipped, the
benchmarks `Real*Benchmark` are left out, and the conformance suite simply has no `real-*` cases to run. With the files in
place, everything runs, and `RealCorpusTest.nothingFromTheCorpusIsPublic` fails if a file that would go into the
repository holds a piece of the corpus: a word, a long line, an address or UID, or a long value. It prints paths and
counts, never a value; rename such a file to `real-*`.

To test against your own calendars, put the anonymizer's output under `corpus/real/<source>/` with a manifest and run
`./gradlew :conformance:updateExpected`.

## Layout

```
corpus/
  real/<source>/<name>.ics                      the anonymizer's output, byte for byte
  real/<source>/<name>.meta.json                the manifest of that file
  real/<source>/<name>.expected-problems.json   the expected outcome of parsing it
  schema/meta.schema.json
  schema/expected-problems.schema.json
```

`<source>` is one of `google`, `apple`, `outlook`, `exchange`, `thunderbird`, `nextcloud`, `yandex`, `university`,
`other`. `<name>` is `<source>-<scenario>-<nn>`, kebab-case, for example `university-group-schedule-01`.

The bytes of a calendar file are part of the test: line endings, the encoding and a byte order mark stay exactly as
the anonymizer wrote them (`.gitattributes` marks `corpus/**` as `-text`). Never open and save these files in an
editor.

## Files

### `<name>.meta.json`

Written by hand, in the key order of `schema/meta.schema.json`:

- `file` — the calendar file name; `source` — equal to the directory name.
- `client`, `clientVersion` — the application that wrote the file (`null` if the version is unknown).
- `exported` — the month of the export, `YYYY-MM`; `method` — `calendar export`, `email attachment`,
  `subscription feed` or `unknown`; `origin` — whose calendar it is and on what grounds it is here.
- `charset` — the encoding of the export: the parser must detect exactly this one, and a single-byte encoding with a
  confidence of at least 90 %. `lineEndings` — `CRLF`, `LF`, `CR` or `mixed`, as in the file.
- `events` — the number of `VEVENT` components; `shiftWeeks` — the anonymizer's `--shift-weeks`;
  `anonymizerCheck` — always `passed`.
- `license` — `private`: the file belongs to whoever exported it and stays out of the repository.
- `features` — what is interesting about the file, without any of its values.

### `<name>.expected-problems.json`

Generated by `./gradlew :conformance:updateExpected` from a lenient parse with the default options: `charset`,
`charsetConfidence`, `truncated`, `counts` (occurrences of every syntax code that occurred, including those beyond the
reporting limit) and `problems` (the problems the listener received, in order, with `code`, `severity`, `line`,
`column` and `offset`, as in the conformance suite's `diagnostics.json`). Canonical JSON, as in
`conformance/README.md`. Review every change before keeping it: the task writes what the parser does now, not what is
right.

## Tests

`RealCorpusTest` in `conformance/src/jvmTest` (JVM only: the files are large and read from disk) checks, for every
file:

- the layout and the manifest (schema, file name, source, line endings);
- a lenient parse matches `<name>.expected-problems.json`;
- the detected charset is the manifest's `charset`, and the number of `VEVENT` is its `events`;
- the byte-stable writer reproduces the input (with CRLF line endings and without a UTF-8 byte order mark; a
  non-UTF-8 input instead reads back as the same tree), the canonical writer's output reads back as an equal tree
  without problems, and the cursor's events give the same tree with the same positions.

Small fragments of these files live in `conformance/ical/real-*` with `"source": "anonymized-real"` and
`"license": "private"`; the conformance suite runs the same round-trip checks on them on every platform. A case from a
real calendar, and only such a case, is named `real-*` (`ConformanceTest.anonymizedRealCasesRoundTrip` checks it).

```bash
./gradlew :conformance:jvmTest          # the golden tests of the corpus, with the conformance suite
./gradlew :conformance:updateExpected   # regenerate the expected files, then review the diff
```
